## 🧩 Exercício 02 — Sistema de processamento de pedidos

### 🎯 Problema

Uma plataforma de comércio eletrônico precisa processar pedidos desde sua criação até a conclusão da entrega.

O processo envolve:

```
Cliente
   ↓
Pedido
   ↓
Estoque
   ↓
Pagamento
   ↓
Preparação
   ↓
Entrega
   ↓
Conclusão
```

Diferentes áreas participam do processo:

-   atendimento;
-   vendas;
-   estoque;
-   financeiro;
-   logística;
-   suporte.

Cada área utiliza informações diferentes e possui responsabilidades próprias dentro do processo.

### 🧠 Sua tarefa

Faça uma **definição completa do problema**, identificando:

1.  **Objetivo**
2.  **Entradas**
3.  **Saídas**
4.  **Regras**
5.  **Restrições**
6.  **Informações não especificadas**
7.  **Atores envolvidos**
8.  **Dependências entre etapas**
9.  **Condições que podem alterar o resultado**

Use:

```
Objetivo:
...

Entradas:
...

Saídas:
...

Regras:
...

Restrições:
...

Informações não especificadas:
...

Atores:
...

Dependências:
...

Condições que alteram o resultado:
...
```

### 🔒 Restrições

-   ❌ Não escrever código.
-   ❌ Não pensar em Java.
-   ❌ Não criar pseudocódigo.
-   ❌ Não criar fluxograma.
-   ❌ Não projetar banco de dados.
-   ❌ Não criar arquitetura.
-   ❌ Não inventar regras de estoque, pagamento ou entrega.
-   ❌ Não definir critérios que não foram apresentados.
-   ❌ Não resolver o problema.

### 🎯 Desafio

Este é o **último exercício de `01-problem-definition`**.

O objetivo é conseguir analisar um problema complexo sem confundir:

```
Entrada
   ≠
Regra
   ≠
Restrição
   ≠
Dependência
   ≠
Condição
   ≠
Saída
```

Também é necessário identificar **o que ainda precisa ser especificado antes que um algoritmo possa ser construído**.
