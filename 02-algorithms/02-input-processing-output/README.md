# 🧩 Input, Processing & Output

> Playground dedicado à prática da relação entre **entrada, processamento e saída** na construção de algoritmos.

## 🎯 Objetivo

Desenvolver a capacidade de identificar:

- quais dados o problema recebe;
- quais operações precisam ser realizadas;
- qual resultado deve ser produzido.

A estrutura fundamental é:

```text
Entrada
   ↓
Processamento
   ↓
Saída
```

## 🧠 Conceito

Um algoritmo geralmente recebe **dados de entrada**, realiza algum **processamento** sobre esses dados e produz uma **saída**.

### 📥 Entrada

São os dados fornecidos ao algoritmo para que o processamento possa ser realizado.

Exemplos:

```text
Nome
Idade
Preço
Quantidade
Nota
```

### ⚙️ Processamento

São as operações realizadas sobre os dados de entrada para produzir o resultado esperado.

Exemplos:

```text
Soma
Subtração
Multiplicação
Divisão
Comparação
Cálculo
```

### 📤 Saída

É o resultado produzido pelo processamento.

Exemplos:

```text
Média
Valor total
Resultado de uma comparação
Mensagem
```

---

## 🔍 Processo

Para cada problema, o processo será:

```text
1. Identificar os dados de entrada
        ↓
2. Identificar o processamento necessário
        ↓
3. Identificar a saída esperada
        ↓
4. Relacionar entrada, processamento e saída
        ↓
5. Verificar se as informações são suficientes
```

O foco é compreender **o fluxo dos dados dentro do problema** antes de implementar a solução.

## 📚 Organização

Os exercícios serão divididos de acordo com o nível de complexidade:

```text
02-input-processing-output/
│
├── 01-basic/
├── 02-intermediate/
└── 03-advanced/
```

### 🟢 Basic

Problemas simples, com entradas, processamento e saídas facilmente identificáveis.

### 🟡 Intermediate

Problemas com múltiplas entradas, diferentes operações e mais de uma saída ou etapa de processamento.

### 🔴 Advanced

Problemas mais complexos, com múltiplos fluxos de dados, dependências entre informações e diferentes resultados possíveis.

## 🔒 Restrições

Durante este Playground:

- Não escrever código.
- Não pensar inicialmente em Java.
- Não criar pseudocódigo.
- Não criar fluxogramas.
- Não resolver problemas além do necessário para identificar o fluxo de dados.
- Não adicionar entradas que não foram apresentadas.
- Não inventar regras de processamento.
- Não confundir entrada com processamento.
- Não confundir processamento com saída.

---

## 💡 Princípio

> **Identifique primeiro os dados que entram, depois o que precisa ser feito com eles e, por fim, o resultado que deve ser produzido.**
